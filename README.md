# A Normalized State-Space Formulation of Stress-Gated Flocking Coordination in Cyber-Physical Energy Systems

Code, synthetic results, and reproducibility tools for "A Normalized State-Space Formulation of Stress-Gated Flocking Coordination in Cyber-Physical Energy Systems".

Citation exports: [CITATION.cff](CITATION.cff), [BibTeX](CITATION.bib), [RIS](CITATION.ris). Cite the software version when reusing code; cite the manuscript for the mathematical formulation, updating its citation when publication metadata becomes available.

## What the formulation does

The controller uses a scalar actuator-rating coordinate and separate perception, drive, and action-selection stages. A stress-gated neighborhood removes separation when both endpoints are below a positive stress tolerance. Optional rest decay attenuates artificial behavioral velocity. A synthetic algebraic plant exposes the mechanism without claiming validated power-flow control.

## Key reusable findings

The separation-only linearized position operator has an anti-consensus coefficient of 125 for the canonical gains. This is an operator coefficient, not a universal trajectory-growth factor. The normalization operator has exact Lipschitz constant 5 at kappa=0.2. State and velocity clipping enforce invariant bounds, while rest decay gives an ultimate velocity bound under continuing forcing.

In the corrected canonical partial-stress example, final utilization falls from 4.489237 to 3.784414 (15.70%) with slightly higher aggregate stress. The result is specific to this configuration: five-topology trials show that partial-stress utilization need not fall. A component ablation separates gating from rest decay.

## Reuse opportunities

This code provides a transparent scalar reference implementation, component ablations, reproducible parameter sensitivity, and a starting point for physical-model and communication studies. It can support analysis of clipped coordination laws and comparisons of activity and stress metrics.

## Quick start

Python 3.12 is the recorded runtime family. From the repository root:

```bash
python -m venv .venv
# Activate the environment for your operating system.
python -m pip install -r requirements-lock.txt
python -m unittest discover -s tests -v
python tools/validate_repository.py
python scripts/reproduce.py --suite canonical --output rerun/results
python tools/validate_results.py --regenerated rerun/results
```

Full regeneration: `python scripts/reproduce.py --suite all --output rerun/results`. All source, small canonical results, traces, and figures are ordinary repository files; no release asset is needed. See [README_RUNNING.md](README_RUNNING.md) and [REPRODUCTION_LEVELS.md](REPRODUCTION_LEVELS.md).

## Data and reproducibility

Every datum is generated by the included synthetic model. No external data, trained weights, network service, or private information is required. Exact parameters, random generator and seeds are recorded in `configs/` and `results/environment.json`. Numerical validation uses declared tolerances; plot bytes and chaotic long-horizon endpoints need not be identical across platforms.

## Scope and limitations

The code fixes ten scalar units with static structural graphs. It does not model actual electrical power flow, battery energy/state-of-charge dynamics, EV deadlines, compressor constraints, noisy sensors or network delays. The trials are synthetic mechanism evaluations. Gating does not guarantee improved physical regulation, reduced energy losses, lower cycling, or communication savings. No full closed-loop stability proof is claimed.
